# 古船模型拆装许可与索具更换追踪台

运行：

```bash
npm start
```

访问 `http://localhost:3038`。数据保存在 `data/model-rigging-calibration.json`。

## 模块划分

- `server.js`：启动入口（只负责监听端口）。
- `src/routes.js`：入口路由，把 HTTP 请求映射到规则并落盘。
- `src/rules.js`：判定规则（拆装单状态机、交付资格、失效重算），不触碰文件系统。
- `src/store.js`：存储读写与主键生成。
- `src/page.js`：页面视图（列表 + 模型详情，刷新后两者一致）。

## 业务规则

- 每个模型同时只能有一张未完结拆装单（进行中 / 返修中 / 待复核）。
- 拆桅前必录：目标索位、替代卷号、监护人（拆装人缺省取模型负责人）；缺少任一项或卷号被其他模型的未完结单占用 → `409`，且不写任何记录。
- 完工登记：原索径、实际索径、绕向、张力四项必录；与开立时的计划值逐项比对（未设计划值的项不参与比对），任一项不符只能转返修，且返修人不能与拆装人相同。
- 返修完成后须由未参与本单的人员（非拆装人 / 返修人 / 监护人）复核；合格才释放原索位并恢复交付资格，不合格退回返修。
- 更换索具批次或修改拆装时间：若模型尚未交付且该单已有结论，则结论失效重算（退回进行中），旧结论存入 `history` 仍可查询；已交付的模型不受影响。
- 存在未完结拆装单时，模型不能置为「已交付」；对已交付模型新开拆装单会自动暂停其交付资格。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/items` | 模型列表（含交付资格、锁定索位、未完结单摘要） |
| POST | `/api/items` | 新增模型 |
| GET | `/api/items/:id` | 模型详情（含全部拆装单及历史） |
| PATCH | `/api/items/:id` | 修改模型；置「已交付」需交付资格已恢复 |
| POST | `/api/items/:id/logs` | 追加备注 |
| POST | `/api/items/:id/action` | 新增帆索任务 |
| POST | `/api/items/:id/orders` | 开立拆装单（409：缺项 / 已有未完结单 / 卷号被占用） |
| GET | `/api/items/:id/orders` | 该模型的全部拆装单 |
| GET | `/api/orders` | 全部拆装单（`?model=`、`?status=` 过滤，旧单可查） |
| GET | `/api/orders/:id` | 拆装单详情（含失效历史 `history`） |
| POST | `/api/orders/:id/complete` | 完工登记（全部相符→合格；任一项不符→转返修） |
| POST | `/api/orders/:id/rework-done` | 返修完成，转待复核 |
| POST | `/api/orders/:id/review` | 复核（复核人须未参与；合格→释放原索位） |
| PATCH | `/api/orders/:id` | 更换索具批次 / 修改拆装时间（未交付结论失效重算） |
| GET | `/api/stats` | 模型与拆装单状态统计 |
